# 代码组成与版本说明

## 已验证的活动构建入口

| 模块 | 活动源码 / 配置 | 作用 |
| --- | --- | --- |
| FAST-LIO2 | `FAST_LIO_ROS2/src/laserMapping.cpp`、`config/mid360.yaml` | 以 MID-360 点云和 IMU 进行 LIO、建图与路径发布。 |
| NDT 场地定位 | `lidar_localization_ros2/src/localization_ver2_1.cpp`、`param/localization.yaml` | 将实时点云和预先生成的场地 PCD 地图匹配，发布定位位姿。 |
| 组件式定位节点 | `lidar_localization_ros2/src/lidar_localization_component.cpp` | 生命周期组件实现，供 `lidar_localization_node` 使用。 |
| NDT 加速 | `ndt_omp_ros2` | OpenMP 加速的 NDT / GICP 算法依赖。 |
| 雷达驱动 | `livox_ros_driver2` | MID-360 设备通信和 ROS 2 消息转换。 |
| IMU / GNSS | `hipnuc_imu`、`hipnuc_imu_can`、`hipnuc_gnss` | Hipnuc 传感器接入。 |

## 版本保留策略

原始工作区含有多个调试阶段的文件，例如 `laserMapping copy*.cpp`、`localization_ver2_1 (副本*).cpp`、`mid360 (副本).yaml` 和 `localization (副本).yaml`。这些文件在仓库中被保留，便于回看参数与算法调整过程；它们不是 CMake 当前默认编译的目标。

当前 CMake 中的关键规则：

- `fastlio_mapping` 编译 `src/laserMapping.cpp`；
- `mid360_localization_node` 编译 `src/localization_ver2_1.cpp`；
- `lidar_localization_component` 编译 `src/lidar_localization_component.cpp`。

因此，若要切换旧版本，应先复制目标版本为上述活动文件名，再重新构建，不建议直接同时修改多份副本。

## 现场地图和数据

场地 PCD 地图、原始点云与录制数据未纳入版本库，以避免仓库膨胀并防止将现场数据公开。`localization.yaml` 当前保留原工作站路径作为记录；部署到新设备时必须将 `map_path` 替换为该设备上的绝对路径。

## 启动顺序建议

1. 配置并启动 `livox_ros_driver2`，确认 `/livox/lidar` 与 `/livox/imu` 的消息频率和时间戳正确；
2. 启动 Hipnuc 包（如果本次任务使用外部 IMU/GNSS）；
3. 建图 / 里程计任务启动 FAST-LIO2；已知场地全局定位任务启动 NDT 定位节点；
4. 使用 RViz 检查 `map`、`odom`、`base_link` 的 TF 链与点云对齐情况。
